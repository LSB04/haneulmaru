NU40 DK + NU-IMU-LSM6DS3TR (Qwiic) 연결

Linux: bash 실행.sh
Windows: 하늘마루_실행.cmd (기존 실행 경로)
수동: python experiments/haneulmaru_pro/stream_server.py --local
의존성: python -m pip install -r requirements.txt

실행하면 PC 렌더러가 열립니다. Windows 실행기는 별도 Chrome 프로필과 고성능 GPU 옵션을 사용합니다.
NUCODE · IMU 패널에서 USB 수신 중 / BLE 수신 유지 상태를 확인한 뒤 'IMU 시작'을 누르세요.
시작 전에는 기존 마우스/휴대폰 조작을 유지합니다. 실제 샘플이 없으면 시작 버튼은 비활성화됩니다.
보드 움직임에 따라 위쪽·아래쪽·왼쪽·오른쪽 표시를 확인하세요.
USB 데이터가 있으면 USB를 사용하고 BLE도 동시에 연결·수신합니다.
USB 데이터가 0.35초 이상 없으면 최신 BLE 데이터로 전환합니다.
양쪽 데이터가 모두 없거나 오래되면 IMU 조작을 해제하고 마우스/휴대폰 조작으로 돌아갑니다.
연결은 계속 재시도합니다. 수신이 복구되면 'IMU 시작'을 다시 누르세요.

IMU 중지: 회전 입력만 멈춥니다. USB와 BLE 연결은 유지합니다.
IMU 시작: 학습된 방향 입력을 다시 사용합니다.
시점 초기화: 카메라를 처음 시점으로 돌립니다.
회전 감도: 같은 움직임에 대한 시점 회전량을 바꿉니다.
IMU 사용 중에는 휴대폰 회전·드래그·확대 입력과 충돌하지 않습니다.
2D 지도에서는 IMU 시점 회전을 적용하지 않습니다.

학습 모델: +imu data/nu40-imu-direction-training(1).json
방향마다 3회 학습한 벡터를 단위벡터로 정규화하고 현재 gx,gy,gz와 비교합니다.
학습 당시 회전 속도에 고정되지 않습니다. 현재 각속도 크기와 샘플 시간으로
화면 회전량을 계산합니다. 20 deg/s 미만은 정지로 처리합니다.
방향 유사도 0.62 미만 또는 두 방향 점수가 비슷한 대각 움직임은 무시합니다.
각속도 기반 상대 시점 조작이며 절대 방위·위치·기울기 추정은 아닙니다.
센서 장착 방향을 바꾸면 모델을 다시 학습해야 합니다.

팀원이 제공한 보드 프로토콜(이번 통합에서는 모의 패킷으로 검증):
USB 115200 baud, NDJSON {v:1,t_ms,ax,ay,az,gx,gy,gz}
가속도 g, 각속도 deg/s, 보드 시간 uint32 ms, 약 20 Hz.
BLE 이름 NU40-IMU, Nordic UART TX 6e400003-b5a3-f393-e0a9-e50e24dcca9e
BLE 17바이트 little endian <BI6h: v,t_ms,ax*10000,ay*10000,az*10000,gx*10,gy*10,gz*10.
현재 보드 펌웨어를 그대로 사용합니다.

USB 자동 검색은 현재 NU40의 VID 239a / PID 80da에 한정합니다.
다른 펌웨어 USB ID 또는 여러 NU40: --imu-port /dev/ttyACM0 (Windows COM 번호)
여러 BLE 보드: --ble-address 장치주소
USB만 사용: --no-ble
기존 폰 입력만 사용: --no-imu
Linux에서 포트 접근 오류가 있으면 계정의 dialout 권한을 확인하세요.
기존 IMU 뷰어가 같은 USB 포트를 읽고 있다면 해당 뷰어를 먼저 종료하세요.
센서 API와 학습 모델 API는 127.0.0.1 로컬 PC 및 현재 실행의 호스트 토큰으로만 접근됩니다.
터널/휴대폰 토큰에서는 접근할 수 없습니다. 서버 재시작 후 PC 패널은 새 호스트 세션을 복구합니다.
기본 Linux 실행은 외부 터널을 만들지 않는 로컬 모드입니다.

팀원 저장소 mymh121-spec/haneulmaru의 949e4e1까지 통합했습니다.
AWS/RTX/정지사진 데이터셋 코드를 유지하며 통합 자동 테스트 28개가 통과했습니다.
실물 보드와 휴대폰을 연결한 전체 시연은 이 통합 작업에서 실행하지 않았습니다.
