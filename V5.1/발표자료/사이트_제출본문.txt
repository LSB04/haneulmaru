# 하늘마루 V5.1
노트북 GPU와 휴대폰·NU40 센서를 연결한 3D 비행 시뮬레이션 및 로컬 AI 장면 설정 도구입니다.

## 해결하려는 문제
다수 비행체의 위치와 고도, 이동 상태를 평면 화면만으로 이해하기 어렵습니다. 별도 고가 장비 없이 노트북과 휴대폰으로 동일한 가상 공간을 보고, 시점을 바꾸며 상황을 확인할 수 있는 인터페이스를 구현했습니다.

## 구현한 기능
- 절차적으로 생성한 지형과 가상 비행장 위에서 합성 비행체를 표시합니다. 3D 전체 보기, 위에서 보는 2D 보기, 드론 시점을 전환합니다.
- 휴대폰 왼쪽 조작부는 전진·후진·좌우 이동, 오른쪽은 상승·하강을 담당합니다. NU40의 IMU 입력으로 시점을 바꾸며, 센서가 끊기면 터치 조작으로 이어갑니다.
- 미확인 합성 객체가 A·B·C로 바뀌는 규칙 기반 이벤트를 시연합니다. V5.1의 A는 다른 객체를 따라가지 않고 지도 중심으로 이동해 대기합니다. B는 화면 효과 후 제거되고 C는 경고 후 지도를 떠납니다. 분류는 합성 시나리오의 난수이며 실제 영상 식별 결과가 아닙니다.
- 자연어 요청을 로컬 AI가 장면 설정 JSON으로 변환합니다. 사용자가 제안을 확인하고 적용하면 개수, 품질, 속도, 시점 등이 바뀝니다.

## 기술 구성
PC의 Three.js/WebGL이 장면을 그립니다. WebRTC로 렌더링 영상을 휴대폰에 보내고 DataChannel로 터치 조작을 받습니다. Android 앱은 USB CDC로 NU40 데이터를 읽고 서버에 전달합니다. Qwen3.5-2B는 ClikaRT 0.6.4의 Vulkan 백엔드로 RTX 2080 Ti에서 추론합니다. AWS 호출은 이 구성에 사용하지 않습니다.

## 검증과 개선
기반 V5에서 지형 생성 CPU 작업 중앙값을 high 200.2→169.2ms, ultra 725.0→295.7ms로 줄였습니다. 워밍업 후 5회 측정한 결과이며 GPU FPS 향상률을 의미하지 않습니다. 동일한 12개 한국어 장면 요청에서 기본 프롬프트의 정확 일치는 Qwen2.5-0.5B 2건, Qwen3.5-2B 9건이었습니다. V5.1 중심 이동과 기존 입력·통신 관련 JavaScript 27개, Python 16개 검사가 통과한 기록이 있습니다.

## 시연 범위
현재 결과물은 합성 환경의 시각화와 조작 프로토타입입니다. 지형은 실측 지도가 아니며, IMU는 방향 입력으로 사용합니다. 실제 드론의 피아 식별·실공간 위치 추정·무장 제어 기능을 시연하지 않습니다. AI 추론은 PC 로컬에서 수행하지만 현재 휴대폰 QR 연결의 HTTPS 터널은 인터넷을 사용합니다. CLIKA 트랙의 오프라인 시연은 로컬 PC 실행 경로에서 별도로 검증합니다.
